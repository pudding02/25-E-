## 一、视觉识别算法原理

### 1.1 经典CV方法：矩形检测

**为什么用矩形检测而不是圆形/HOG/模板匹配？**

电赛E题的靶标是**黑白矩形边框**，具有明确的几何特征：
- 闭合四边形，四个角点清晰
- 内部白色/外部背景可区分
- 对边平行、邻边垂直
- 面积在画面中占比可预测

这些特征使得经典CV方法比YOLO等神经网络更简单、更快、不需训练数据。

**通用算法流程（与硬件平台无关）**：

```
                        ┌──────────┐
                        │ 摄像头帧  │
                        └────┬─────┘
                             ▼
                    ┌───────────────┐
                    │  预处理        │
                    │ (灰度/HSV掩膜) │
                    └───────┬───────┘
                            ▼
                    ┌───────────────┐
                    │  边缘检测      │
                    │ (Canny/Sobel) │
                    └───────┬───────┘
                            ▼
                    ┌───────────────┐
                    │  形态学处理    │
                    │  (膨胀/闭运算) │
                    └───────┬───────┘
                            ▼
                    ┌───────────────┐
                    │  轮廓查找      │
                    │ findContours  │
                    └───────┬───────┘
                            ▼
                    ┌───────────────┐
                    │  多边形逼近    │
                    │ approxPolyDP  │
                    └───────┬───────┘
                            ▼
                    ┌───────────────┐
                    │  四边形筛选    │
                    │  (多维度评分)  │
                    └───────┬───────┘
                            ▼
                    ┌───────────────┐
                    │  对角交点计算  │
                    │  → 靶心坐标    │
                    └───────────────┘
```

**各步骤参数调优指南**：

| 步骤 | 参数 | 效果 | 调参方向 |
|------|------|------|---------|
| HSV掩膜 | V通道上限 | 过滤背景 | 环境暗→降低上限(60-80)；环境亮→提高(90-120) |
| Canny | low_threshold | 边缘敏感度 | 弱边缘→降低(30-50)；噪点多→提高(60-80) |
| Canny | high_threshold | 强边缘阈值 | 一般为low的2-3倍 |
| 膨胀 | kernel大小 | 连接断裂边缘 | 矩形框完整→缩小(3×3)；断裂多→增大(7×7) |
| 膨胀 | iterations | 膨胀次数 | 同上，一次调整一步 |
| approxPolyDP | epsilon比例 | 逼近精度 | 矩形变形大→增大(0.03-0.05)；矩形标准→减小(0.01-0.02) |
| 面积筛选 | min_area | 过滤噪点 | 画面上矩形大→提高；矩形小/远→降低 |

### 1.2 YOLO目标检测方法

当矩形特征不明显（变形、遮挡、光照极端），或需要检测**非矩形目标**时，使用YOLOv8神经网络。

**与经典CV的互补关系**：

| 维度 | 经典CV矩形检测 | YOLOv8 |
|------|:-----------:|:------:|
| 需要训练数据 | 否 | 是（需要标注） |
| 对矩形形变的鲁棒性 | 中（依赖角点清晰） | 高 |
| 对遮挡的鲁棒性 | 低 | 中高 |
| 对光照变化的鲁棒性 | 低 | 高（增强后） |
| 检测非矩形目标 | 不支持 | 支持 |
| 计算资源需求 | 低 | 中高（需NPU加速） |
| 输出信息 | 4角点+中心 | 包围框+类别+置信度 |
| 部署复杂度 | 低 | 中（需模型转换） |

### 1.3 双模式切换

```
        config.json                 main.py 入口
     detection.mode = ?          if MODE == "yolo":
             │                       run_yolo()
             ▼                   else:
   ┌──────────────────┐              run_cv()
   │ cv   → 矩形检测   │
   │ yolo → KPU检测    │        两模式统一输出:
   └──────────────────┘        物体中心 → (dx,dy) 偏差 → servo_send
```

- CV 模式：矩形四边形中心 `quad_center(box)` 为追踪点，精度高、无帧率损失
- YOLO 模式：识别框中心 `(x+w//2, y+h//2)` 为追踪点，鲁棒性好、支持任意类别
- 实际实现见 [k230/main.py](file:///c:/Users/12553/Desktop/视觉/复刻/k230/main.py) 第九节「入口 — 模式切换」

## 二、云台控制理论

> 当前工程：**双轴均为 Emm42_V5.0 闭环步进驱动器**（42 电机），
> **两轴速度模式相同**——串口「速度模式」：|像素偏差| 线性映射成转速，死区内停；
> 丢靶时 yaw 可「预判续追」（见 2.2），pitch 丢靶即停。
> 协议与实现见 k230/main.py 与项目根目录 `接线图.md`；
> 安装纪律：上电前把云台俯仰摆到行程中部（步进断电会因重力下垂），两轴均建议机械居中安装。
> （历史：pitch 曾试行「位置模式」——角度记账 + 绝对位置目标 + 上电清零，实测驱动器②不工作，已改回与 yaw 相同的速度模式。）

### 2.1 双轴控制结构

```
      dx (像素偏差)                          yaw 输出
画面中心 ──────→ |dx|线性映射RPM ──→ Emm42「速度模式」──→ 云台左右
                  (死区内停转)

      dy (像素偏差)                          pitch 输出
标定中心 ──────→ |dy|线性映射RPM ──→ Emm42「速度模式」──→ 云台俯仰
                  (死区内停转)
```

**控制参数（泛化的 P 控制）**：

| 参数 | 作用 | 典型范围 | 过大导致 | 过小导致 |
|------|------|---------|---------|---------|
| `min_rpm / max_rpm` | 转速区间 | 1~50 | 小偏差也冲过头 | 跟踪迟缓 |
| `dx_full_px / dy_full_px` | 达到满速的偏差阈值 | 100~300 | 小偏差就满速(更凶) | 转速爬升太慢 |
| `deadband_px` | 中心死区 | 3~10 | 对不中 | 中心抖动 |
| `reverse` | 方向翻转 | — | — | 方向反了就改这个 |

**经验**：

```
两轴相同: |偏差|≤死区停转 → min_rpm 起步, |偏差|≥dx/dy_full_px 达 max_rpm
方向反  : motor.reverse / pitch_motor.reverse 翻转
历史参考(旧舵机架构): 精细对准 Kp≈0.084 / 快速跟踪 Kp≈0.8 / Y轴系数取反
```

### 2.2 追踪状态与丢靶行为

当前实现只有两个视觉状态（`gimbal_send` 的 status 参数）：

```
"track" — 正常追踪:
          yaw  : |dx| 线性映射转速; 死区内停转
          pitch: |dy| 线性映射转速; 死区内停转
"lost"  — 目标丢失:
          yaw  : 丢靶预判——最后偏差 |dx| ≥ coast_edge_px(默认160) 时, 不立即停,
                 朝最后方向按最后偏差映射的转速续转 coast_ms(默认800ms) 去找
                 (无目标追踪); 超时停转, 期间重新捕获立即恢复常规追踪。
                 未达门槛(目标最后在画面中部)或 coast_enabled=false → 立即停转。
          pitch: 立即停转(不参与预判)
```

> 历史联系：早期方案用 `mode`/`keycnt` 组合状态机做扫描/复位（丢失后先短暂保持再搜索）。
> 当前工程已落地简化版「续追式预判」（见上）；若要扩展成完整扫描/复位状态机，继续在 `gimbal_send` 的 "lost" 分支与 `coast_step` 上扩展即可。
